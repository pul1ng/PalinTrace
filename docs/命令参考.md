# 命令参考

本文对应 0.1.0 的实际命令。安装和单任务上手见 [README](../README.md)。示例在项目根目录执行，统一使用 `.venv/bin/palin`；安装到 PATH 后也可使用 `palin`、`palinreplay` 或 `pal`。

## 命令概览

```text
palin
├── download
│   ├── dataset          下载原始任务数据
│   └── mirror           拉取、核验任务镜像
├── convert              将本地数据转换为任务包
├── inspect              查看一个任务
├── preload              初始化并冻结只读 C0 基座
├── record
│   ├── run              复用 C0，运行并录制
│   ├── inspect          查看轨迹、节点和完整性
│   ├── export           导出可阅读的轨迹证据
│   ├── verify-restore   独立恢复、完整比较文件并清理
│   └── visualize        生成离线轨迹可视化
└── replay               从已提交节点恢复并真实执行固定历史工具
```

从零开始的顺序为：下载数据 → 转换任务包 → 准备镜像 → preload → record → 查看／校验。也可在转换后使用顶层 `inspect` 核对任务。

## 通用约定

- 输出目录或报告文件须不存在，命令不会覆盖已有结果。重新录制可复用原基座，但须使用新的运行目录。
- `convert` 和查看命令不调用模型。真实 `record run` 会请求模型服务；恢复校验不重执行历史工具。`replay` 不调用模型，但真实执行所选范围的历史工具。
- 普通任务查看和轨迹元数据查看不需要 Docker；镜像准备、preload、record、快照检查、导出、恢复校验和 replay 需要可访问相应 Docker 资源。
- Docker 连接顺序为 `DOCKER_CONTEXT`、`DOCKER_HOST`、当前 CLI context；运行层仅支持本地 Unix socket。
- 进度和错误写入 stderr；命令结果写入 stdout。错误以 `error:` 开头。
- 数据下载、转换、镜像清单和 preload 在成功后发布；失败时已下载的 Docker 缓存可能保留。录制失败会保留报告、已提交节点和不完整尾部，不自动续跑。

| 退出码 | 含义 |
|---|---|
| `0` | 命令成功；录制达到预算后的正常结束也可以返回 0，不代表解题正确 |
| `1` | 操作失败或检查发现完整性问题 |
| `2` | 命令行参数解析错误；Replay 也用此码表示存在比较差异，无论是否执行完成 |
| `3` | Record 存在未完成步骤 |
| `130` | preload、Record 或 Replay 被取消 |

所有命令都支持 `--help`。当前文件后端统一为 Btrfs。

## 默认输出

省略 `--output` 时，产物保存在执行命令时所在目录的 `outputs/` 下。名称使用本地时间 `YYMMDD_HHMMSS_名称`：下载和转换取数据集名称；预载、录制和可视化优先取任务 ID，无任务 ID 时使用来源名称。已有时间戳前缀不会重复拼接。

| 命令 | 默认产物 |
|---|---|
| `download dataset` | `outputs/download/时间戳_数据集/` |
| `convert` | `outputs/convert/时间戳_数据集/` |
| `preload` | `outputs/preload/时间戳_任务ID/` |
| `record run` | `outputs/record/时间戳_任务ID/` |
| `replay` | `outputs/replay/时间戳_任务ID/` |
| `record export` | `outputs/export/时间戳_任务ID/` |
| `record verify-restore` | `outputs/verify-restore/时间戳_任务ID_节点.json` |
| `record visualize` | `outputs/visual/时间戳_任务ID.html` |

显式指定输出路径时原样使用，不额外添加目录或时间戳。恢复报告沿用 `--report FILE`，也接受 `--output FILE`。同秒同名时提示路径已存在，可稍后重试或指定其他路径。Quickstart 同一轮共用一个时间戳；其 `--output DIR` 指定包含各类型子目录的产物根目录。

镜像准备仍在输入任务包内保存 `images.json`，查看命令只输出到终端。Docker 镜像和 Btrfs 池仍由 Docker 管理。旧的录制目录可以继续作为输入，不自动迁移。

下文路径中的 `261031_131022` 仅为示例，请替换为上一条命令实际打印的路径。

## download dataset

```bash
.venv/bin/palin download dataset \
  --source swebench_lite
```

| 参数 | 必填／默认值 | 说明 |
|---|---|---|
| `--source NAME` | 必填 | `swebench_lite`、`swebench_full` 或 `swebench_verified` |
| `--output DIR` | 可选 | 新下载目录；默认在 `outputs/download/` 生成 |
| `--split NAME` | `test` | 数据集拆分 |
| `--revision REF` | 解析远程默认版本 | 固定数据集版本，记录实际解析的提交 |
| `--limit N` | 全部 | 仅保存前 N 行，N 为正整数 |
| `--format FMT` | `jsonl` | `jsonl` 或 `parquet` |

在线数据下载需要 `swebench` extra；Parquet 下载或读取另需 `parquet` extra。下载目录包含 `fetch.json` 和行数据文件，记录来源、实际版本、行数及摘要。下载不转换数据，也不拉取任务镜像。

## convert

```bash
.venv/bin/palin convert --input outputs/download/261031_131022_swebench_lite \
  --instance-id astropy__astropy-12907
```

| 参数 | 必填／默认值 | 说明 |
|---|---|---|
| `--input PATH` | 必填 | 下载目录、本地 JSON／JSONL／NDJSON／Parquet 文件或分片目录 |
| `--output DIR` | 可选 | 新任务包目录；默认在 `outputs/convert/` 生成 |
| `--source NAME` | 可从 `fetch.json` 推断 | 裸文件或无 `fetch.json` 的目录必须指定 |
| `--instance-id ID` | 全部 | 选择任务，可重复 |
| `--limit N` | 全部 | 选择后保留前 N 个任务 |

含 `fetch.json` 的目录会核对来源、行数与摘要；显式 source 不得与其冲突。转换不联网，也不访问 Docker。CLI 生成 `linux/amd64` 镜像引用；转换成功仅代表任务包已生成，镜像仍待准备。

产物包括根目录的 `manifest.json`，以及每个任务的 `task.json`、题面和独立评测材料目录。Agent 输入与隐藏评测材料分开。镜像准备结果另存为 `images.json`。

本地合成样例可离线转换、查看，但没有可供真实录制的任务镜像：

```bash
.venv/bin/palin convert --source swebench_lite \
  --input examples/swebench.sample.json --output outputs/convert/261031_131022_sample
.venv/bin/palin inspect outputs/convert/261031_131022_sample/example__repo-1 --agent-input
```

## inspect

```bash
.venv/bin/palin inspect outputs/convert/261031_131022_swebench_lite/astropy__astropy-12907 --agent-input
```

参数 `PATH` 是单个任务目录，不是任务包根目录。`--agent-input` 仅输出面向 Agent 的内容，隐藏评测材料；不带该参数时输出完整任务描述。此命令核验任务材料，不证明镜像已准备或任务已运行。

## download mirror

```bash
.venv/bin/palin download mirror outputs/convert/261031_131022_swebench_lite
```

输入为含 `manifest.json` 的任务包根目录。命令按引用和平台去重，拉取全部选中任务的镜像，核验实际平台及 image ID，生成绑定任务包摘要的 `images.json`，不启动容器。默认显示总进度和 Docker 原生逐层下载／解包进度。

唯一附加参数为 `--archive-dir DIR`：额外保存 Docker 镜像 tar 及其 SHA-256。需要归档时，在首次准备时用下面这条命令替代上面的命令：

```bash
.venv/bin/palin download mirror outputs/convert/261031_131022_swebench_lite \
  --archive-dir outputs/image-archives/261031_131022_astropy
```

已有 `images.json` 时拒绝覆盖，不支持追加镜像或补归档。此命令没有任务筛选参数，也没有 `--output`；先在转换阶段选择任务。Docker 镜像 tar 不包含后续 C0 或录制快照。

### 指定镜像来源

镜像引用在转换时确定，`download mirror` 不自动切换来源。若 Docker 代理返回 allowlist／白名单错误，可使用 Python 转换接口的 `image_map` 生成一个新任务包。

以下使用[现有验收记录](validation/btrfs-record-20261030/images.json)中的镜像来源；访问能力取决于当前网络及 Docker 配置：

```bash
.venv/bin/python - <<'PY'
from palinreplay.tasks import convert

convert(
    "outputs/convert/261031_131022_swebench_lite_direct",
    input_path="outputs/download/261031_131022_swebench_lite",
    ids=["astropy__astropy-12907"],
    image_map={
        "astropy__astropy-12907":
        "registry-1.docker.io/swebench/sweb.eval.x86_64.astropy_1776_astropy-12907:latest"
    },
)
PY

.venv/bin/palin download mirror outputs/convert/261031_131022_swebench_lite_direct
```

后续 preload 和 record 均使用这个新任务包及相应的新输出目录。CLI 不提供 `--image-map` 或镜像源切换参数。

## preload

```bash
.venv/bin/palin preload outputs/convert/261031_131022_swebench_lite
```

| 参数 | 必填／默认值 | 说明 |
|---|---|---|
| `SOURCE` | 必填 | 已准备镜像的任务包，或独立 preload 输入 JSON |
| `--output DIR` | 可选 | 新基座目录；默认在 `outputs/preload/` 生成 |
| `--task-id ID` | 单任务可省略 | 多任务包中选择一个任务 |
| `--init FILE` | 保留镜像并做基本检查 | 额外初始化步骤及就绪检查 JSON |
| `--public-env KEY` | 使用默认公开变量集合 | 额外允许保存的容器环境变量名，可重复 |

命令获取来源镜像、创建临时容器、执行初始化、停止并冻结文件状态，将根文件系统导入 Btrfs 后保存只读 C0。需要的来源镜像可以在此阶段拉取；`record run` 不自动拉取镜像。

默认只检查 shell、工作目录与 `BASH_ENV`，不把 instruction 当作脚本执行。自定义初始化 JSON 的格式为：

```json
{
  "commands": ["python -c 'import astropy'"],
  "checks": ["test -d /testbed", "python -c 'import astropy'"],
  "timeout_sec": 600
}
```

`commands` 默认为空；`checks` 至少一项且全部成功，冻结前会再次执行。每条命令使用新的配置 shell，`cd`、`export` 不会跨命令保留。`timeout_sec` 是整个初始化阶段的上限，默认 600 秒。

将上述 JSON 保存为本地文件，例如 `data/init-astropy.json` 后执行：

```bash
.venv/bin/palin preload outputs/convert/261031_131022_swebench_lite \
  --init data/init-astropy.json \
  --output outputs/preload/261031_131022_astropy_initialized
```

独立输入 JSON 至少包含 `image`、`platform` 和 `instruction`。`image` 接受完整本地 `sha256:…` ID 或 `repository@sha256:…` 摘要；`platform` 为 `linux/amd64` 或 `linux/arm64`。可选 `env`、`workdir`、`shell`、`timeout_sec`、`task_id`、`image_reference` 和 `repo_digests`。record 复用时会比较完整输入与任务包配置，手写输入不会自动匹配任意任务。

成功输出 `Preload: preload:sha256:…`、路径及耗时。基座目录包含 `c0.json`、`c0.checksum.json` 和 `build.json`；实际文件位于外部 Docker volume。`--public-env` 接收变量名而非值，变量必须存在，不会复制宿主环境。

## record run

```bash
.venv/bin/palin record run outputs/convert/261031_131022_swebench_lite \
  --preload outputs/preload/261031_131022_astropy__astropy-12907 \
  --max-steps 2
```

| 参数 | 必填／默认值 | 说明 |
|---|---|---|
| `DATASET_DIR` | 必填 | 含 `manifest.json` 与 `images.json` 的任务包根目录 |
| `--preload DIR` | 必填 | 为同一任务输入生成的 Btrfs 基座 |
| `--output DIR` | 可选 | 新录制目录；默认在 `outputs/record/` 生成 |
| `--task-id ID` | 单任务可省略 | 多任务包中选择一个任务 |
| `--llm-config FILE` | 按下文规则加载 | 模型配置 TOML |
| `--max-steps N` | `20` | Agent 步数预算，正整数，C0 不计入 |
| `--max-tokens N` | `8192` | 单次模型输出 token 上限 |
| `--time-limit SEC` | `0` | 原生 Agent 运行时间预算，0 为禁用 |
| `--cost-limit VALUE` | `0` | 原生 Agent 估算费用预算，0 为禁用；未知费用不表示免费 |
| `--retry-attempts N` | `1` | 每次模型查询的原生尝试次数，SDK 自动重试关闭 |
| `--network MODE` | `bridge` | `bridge` 或 `none` |
| `--public-env KEY` | 默认公开变量集合及基座已保存变量 | 额外允许记录的容器环境变量名，可重复 |
| `--progress MODE` | `auto` | `auto`、`plain` 或 `off` |
| `--debug` | 关闭 | 显示详细阶段耗时和计时汇总；不影响计时采集与保存 |

`auto` 在终端显示动态进度，重定向时使用普通日志。步数条表示已提交步骤与预算，不表示解题完成百分比。

录制始终采集阶段、模型请求、工具执行及快照保存的耗时，写入 `report.json.debug_timing`，无需开启 `--debug`；该参数只控制详细计时的终端显示。`--progress off` 关闭实时进度，开启 `--debug` 时仍会在结束后显示计时汇总。计时含父子阶段，`duration_sec` 包含子阶段，`self_sec` 扣除直接子阶段，不应把父子耗时重复相加。保留原有采集上限，达到上限时报告会标记明细不完整；旧录制不会补生成计时数据。

运行创建独立可写任务根目录，引用已有 C0；C1 以后只保存 Btrfs 快照增量，不逐步导出、打包或全量扫描文件。快照保存时暂停任务进程、同步写入；这不构成应用事务或进程检查点。

输出为 `report.json` 和 `record/`。报告区分主要错误与清理错误；失败时保留已提交历史和不完整尾部，不自动覆盖或续跑。模型结果保存、Agent 接纳和节点提交分别记录，半个工具组不会作为完整节点发布。

### 模型配置

文件选择顺序为 `--llm-config FILE`、`PALINREPLAY_LLM_CONFIG` 指定路径、当前目录下的 `config/llm/llm.toml`。未选中可读取文件时可仅使用环境变量；显式 `--llm-config` 路径不存在会报错。不会自动加载 `.env`。

TOML 必须包含 `[llm]`，字段优先级为 TOML 值高于环境变量，最后使用默认值；选择其他 TOML 时不会叠加默认文件。

| 字段 | 环境变量／默认值 | 说明 |
|---|---|---|
| `model` | `OPENAI_MODEL`，必填 | 服务支持的模型 ID |
| `api_key` | `OPENAI_API_KEY`，必填 | API Key；模板默认从环境变量提供 |
| `base_url` | `OPENAI_BASE_URL`，默认 `https://api.openai.com/v1` | Chat Completions 服务地址 |
| `timeout` | 默认 `60` 秒 | 单次模型请求超时 |
| `max_retries` | 默认 `0` | 库客户端配置；Record 固定关闭 SDK 重试，使用 `--retry-attempts` |

模板见 [llm.example.toml](../config/llm/llm.example.toml)。任务容器的环境变量由任务与基座配置提供，与模型客户端凭据分开；`--public-env` 只声明允许保存的变量，不负责注入值。

## record inspect

```bash
.venv/bin/palin record inspect outputs/record/261031_131022_astropy__astropy-12907
.venv/bin/palin record inspect outputs/record/261031_131022_astropy__astropy-12907 --check --json
.venv/bin/palin record inspect outputs/record/261031_131022_astropy__astropy-12907 --node C0
```

`PATH` 接受录制目录或含 `catalog.sqlite` 的 `RecordStore` 目录。

| 参数 | 说明 |
|---|---|
| `--run ID` | 选择一个 run |
| `--node SELECTOR` | 选择 `C0`、`C1` 等标签或完整 node ID，显示上下文与调用 |
| `--execution ID` | 查看一次模型或工具执行的原始结果、交付与接纳材料 |
| `--check` | 核验本地材料摘要、引用关系及外部快照身份与只读属性 |
| `--json` | 输出机器可读 JSON |

`--node` 与 `--execution` 互斥。节点选择须唯一，多 run 时使用 `--run` 或完整 node ID。元数据查看不等于外部文件快照已验证；`--check` 不全量读取任务文件，Btrfs 在实际读取时检查数据校验和。

录制完整性与结束状态分开显示。没有结束记录的运行显示为 `unfinalized`，不能据此判断原进程仍在运行。

## record export

```bash
.venv/bin/palin record export outputs/record/261031_131022_astropy__astropy-12907
```

`PATH` 为录制或 Store 目录；`--output DIR` 可选，默认输出到 `outputs/export/` 下的带时间戳目录。`--format` 默认为 `trajectory`，生成 `trajectory.json` 和 `export.json`，导出前核验材料，因此需要对应 Btrfs 池可访问。

导出保留消息、调用证据、上下文和运行状态，不含 Docker 镜像或 Btrfs 池，不能用于文件恢复。参数仍可接受 `--format bundle`，但当前 Btrfs 记录明确拒绝便携 bundle。完整但失败或中断的记录可以导出并保留其状态；原始工具输出和文件内容不会自动脱敏。

## record verify-restore

```bash
.venv/bin/palin record verify-restore outputs/record/261031_131022_astropy__astropy-12907 \
  --node C0
```

| 参数 | 必填／说明 |
|---|---|
| `PATH` | 必填，录制或 Store 目录 |
| `--node SELECTOR` | 必填，已提交节点的标签或完整 ID |
| `--report FILE`／`--output FILE` | 可选，默认在 `outputs/verify-restore/` 生成 JSON；自定义路径须位于 Store 外且父目录已存在 |
| `--run ID` | 多 run 时选择一个 run |

命令从选定快照创建独立可写环境，完整读取并比较声明范围内的文件，随后清理临时容器与工作区，保留原始只读快照。它不重执行历史命令，也不恢复 Agent 会话。

`rootfs-files-v1` 支持文件内容、路径、模式位、UID/GID、软链接目标、硬链接关系和普通文件秒级修改时间。排除 `/proc`、`/sys`、`/dev`、`/.dockerenv` 以及 Docker 注入的 hosts／hostname／resolv.conf。ACL、扩展属性、文件 capability、目录及软链接时间戳、进程内存、服务运行现场和外部挂载卷不在当前恢复保证内。

已有 Btrfs 验证结果见[10 镜像验收报告](validation/btrfs-record-20261030/README.md)。

## record visualize

从已有的 Btrfs 录制目录生成离线页面：

```bash
.venv/bin/palin record visualize outputs/record/261031_131022_astropy__astropy-12907
```

参数只有 `RUN_DIR` 和可选的 `--output FILE`。默认页面位于 `outputs/visual/`，命令结束会打印路径；可指定 `--output page.html`。原示例脚本仍可作为兼容入口使用。

用浏览器打开生成的 HTML，可选择节点、查看上下文与模型／工具调用、搜索记录，以及查看耗时和 Btrfs 快照信息。无需开启 `--debug`；旧记录缺少详细计时时使用等宽事件视图，缺失指标显示“未采集”。当前要求一条完整提交的轨迹，不展示未完成步骤的尾部。

顶部四个阶段使用不同颜色，与下方时间轴共用比例和边界。悬停阶段时，对应事件、步骤列表和节点高亮，其余内容变暗；移开鼠标后恢复。较短阶段的完整名称和耗时可通过悬停查看，点击仍会定位到该阶段。

底部“自动播放”按记录顺序切换详情，并让阶段高亮、时间轴游标和列表滚动跟随。支持暂停后继续、从头播放、1×／2×／4×演示速度及循环；默认 2×，每条记录展示约 0.8 秒，演示节奏不代表原始执行耗时。播放遵循当前筛选，手动选择记录、修改筛选或离开页面时暂停。已有 HTML 需要重新生成才能使用新功能。

池镜像物理占用和相对 C0 的增长来自各节点保存时的测量，包含共享数据与池内其他工作区，不表示每个快照的独占空间。轨迹元数据体积单独展示。

生成页面只读取已有轨迹与诊断材料，不连接 Docker、不挂载存储池或扫描任务文件。页面不携带文件快照正文，浏览播放不执行 Replay 或环境恢复。

## replay

从已提交节点恢复，在同一真实工作区按固定历史执行后续工具，不调用模型。来源必须包含所选范围的完整材料，且原 Docker daemon、Btrfs 池和镜像仍可访问。

```bash
.venv/bin/palin replay "$PALIN_RUN" --from C2 --to C4
.venv/bin/palin replay "$PALIN_RUN" --from C2 --to C4 \
  --validation lenient --output outputs/replay/lenient-C2-C4
.venv/bin/palin replay "$PALIN_RUN" --from C2 --to C4 \
  --validation strict --output outputs/replay/strict-C2-C4
```

| 参数 | 必填／默认值 | 说明 |
|---|---|---|
| `SOURCE` | 必填 | Record store 或包含 `record/` 的运行／bundle 目录 |
| `--from NODE` | 必填 | 恢复基线，Cn 或完整节点 ID；成为新 C0，不重执行该节点 |
| `--to NODE` | 启动时最后一个已提交节点 | 固定历史范围的包含式终点 |
| `--run ID` | 可选 | 选择来源 Run |
| `--output DIR` | 新默认目录 | 保存报告与独立录制；不能覆盖现有结果或来源 |
| `--validation {strict,lenient}` | `lenient` | lenient 保存确定差异并继续；strict 在首次差异后停止 |
| `--progress {auto,plain,off}` | `auto` | 终端动态进度条，重定向时普通文本；plain 固定文本，off 关闭进度 |

进度显示历史读取、节点恢复、基线校验、逐步执行与保存、文件校验和资源清理，并展示来源节点到本次节点的对应关系、已完成步数和耗时。总步数不包含恢复基线，例如 C1→C44 为 43 步；未完成工具组和校验故障不会推进计数，中途停止也不会补满进度。步数完成不表示校验通过，仍以最后的执行状态和校验结果为准。进度输出到 stderr，最终报告输出保持原样。

默认 lenient 模式保存确定的工具退出码、原始输出或文件状态差异，继续当前工具组和后续历史步骤。每个完整步骤后仍执行现有增量文件比较，包括工具返回已出现差异的步骤，然后在本次真实工作区和上下文上继续。

strict 模式在首次差异后停止。中途工具差异保留已执行调用与不完整尾部，不伪造完整节点；完成整个工具组时保留完整实际节点。两种模式的比较规则相同，区别是发现确定差异后是否继续执行。

Python API `palinreplay.replay.session.run_replay(..., validation_mode="lenient")` 使用相同默认值；传入 `validation_mode="strict"` 可选择遇差异停止。

终端与 `report.json` 分别报告执行和校验结果：

| 字段 | 取值 | 含义 |
|---|---|---|
| `execution_status` | `completed` | 完成指定范围的全部历史步骤 |
| | `stopped` | 因差异留下尚未执行的工具调用或步骤 |
| | `failed` | 材料、恢复、执行、校验或清理故障 |
| `validation_status` | `match` | 全部必要比较完成且一致 |
| | `difference` | 发现过确定差异，之后保持此结果 |
| | `incomplete` | 检查未完成且尚未发现差异 |

仅 `completed + match` 返回 `0`。存在差异返回 `2`，包括 `stopped + difference` 和 `completed + difference`；最终完整步骤发生差异也属于后者。故障始终返回 `1`，即使此前已发现差异或全部比较一致。故障前的首次差异不会丢失，完成但有差异不会显示为 MATCH 或“提前停止”。用户取消仍返回 `130`。

`first_difference` 保存首次差异的原因、来源节点／序号、工具位置及详细比较结果；`steps` 保存后续所有工具和文件比较，`mappings` 关联来源与实际节点。后续步骤的 `starting_divergent` 表示开始时已有差异；后续增量局部匹配不能证明整个工作区已恢复一致。报告保存 `validation_mode`（`strict` 或 `lenient`），并保存使用量、计时和清理诊断；实际返回、上下文和快照关联保存在独立的 `record/`，本次录制配置保存 `replay.validation_mode`。旧 `status` 字段保留兼容，故障优先。

两种模式遇到损坏材料、恢复失败、快照读取失败、校验异常或不确定工具结果仍停止。初始基线完整校验仍须通过。时间戳与 `.pyc` 比较规则保持原样，不增加忽略项或全量扫描，不修改历史命令、不自动重试、不修复文件、不用来源快照覆盖实际结果，来源轨迹不变。

## 常见问题

| 现象 | 处理 |
|---|---|
| 输出已存在 | 使用新目录；镜像准备失败后也先检查已有缓存或归档 |
| 缺少 `images.json` | 对转换后的任务包执行 `download mirror` |
| 镜像下载被白名单限制 | 核对 Docker 代理；按“指定镜像来源”重新转换任务包 |
| 找不到工具／启动器镜像 | 先执行 README 中两条 Docker 构建命令，平台需匹配任务 |
| preload 与任务不匹配 | 选择生成该基座时使用的完整任务配置，或重新构建基座 |
| 原镜像已删，环境变量不全 | 恢复相应来源镜像，或用完整任务配置重新生成基座 |
| 快照或池找不到 | 确认使用原 Docker daemon，且被引用的 volume 仍存在 |
| 修改 `--output` 后 Docker 数据盘仍增长 | 输出目录只保存描述与证据；实际镜像和快照位置仍由 Docker 决定 |
| 找不到某个 Cn | 先 inspect 查看实际已提交节点；预算和失败都可能使运行提前结束 |
